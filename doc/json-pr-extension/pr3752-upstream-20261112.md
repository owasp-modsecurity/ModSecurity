## Build and run every suite

Use the dependencies and source-build settings in
[the JSON workflow](../../.github/workflows/json-tests.yml) and the project's
[official README](../../README.md). From a fresh checkout of the PR head:

```sh
git submodule update --init --recursive
sh -e ./build.sh
./configure --enable-assertions=yes --enable-parser-generation=no \
  --without-geoip --with-yajl --with-pcre2 --with-curl --with-libxml \
  --with-lua --with-lmdb --with-maxmind --with-ssdeep=/usr
make -j2
python3 test/json-baseline/tools/build.py \
  --source "$PWD" --source-ref "$(git rev-parse HEAD)" \
  --output ../json-probes-pr3752
python3 test/json-baseline/tools/run_all.py \
  --probes ../json-probes-pr3752 --profile all \
  --output ../json-results-pr3752
```

Both output directories must be new and outside the source checkout. The final
command runs all seven suites, records per-suite reports/logs and returns
nonzero if any cases fail or are blocked. It must not be advertised as a green
command while requirements remain unmet. Use `--profile characterization` and
`--profile requirements` with separate new output directories to inspect the
two groups independently.

The included workflow runs both profiles as independent matrix jobs with
`fail-fast: false`, retains genuine failure status and uploads evidence even
when a job fails. Ordinary `make check` still runs the native fixture; the
additional standalone suites use the runner above and the added workflow.
