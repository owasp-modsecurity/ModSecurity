# Repository map: ModSecurity v3

## Scope and reading order

This map describes the official source tree of `owasp-modsecurity/ModSecurity`, branch `v3/master`, at commit `effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729`. The linked sources remain pinned to that commit. It explains every top-level entry and the main internal work areas; it does not claim that every function has been individually reviewed. Its sources are the [Git tree](https://github.com/owasp-modsecurity/ModSecurity/tree/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729), the [build files](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/Makefile.am) and the implementations cited for each topic.

`AGENTS.md` and `.codex/` are instructions added for this working repository. They are not part of the upstream commit examined here. The product descriptions below refer to upstream code; suggestions about reading order and task decomposition are recommendations from this documentation.

Suggested starting points:

1. [architecture.md](architecture.md) explains a transaction's path through the library.
2. This file maps directories and file types.
3. [feature-map.md](feature-map.md) connects specific questions to implementations and existing tests.
4. [cpp-guide.md](cpp-guide.md) explains the C++ and C interfaces used in the code.
5. [build-and-test.md](build-and-test.md) and [configuration-and-rules.md](configuration-and-rules.md) cover building, testing and rules.

## 1. What this repository builds

The main library target is `libmodsecurity.la`. Its source files are assembled in `src/Makefile.am`, including transactions, rule evaluation, parsers, actions, operators, variables, body parsers and logging. The top-level Automake entry traverses `others`, `src`, `doc`, `tools` and, depending on configuration, `examples` and `test`. Sources: [library target](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/Makefile.am#L11-L14), [source files](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/Makefile.am#L255-L288), [subdirectories](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/Makefile.am#L2-L17).

HTTP data enters the library through the `Transaction` API or its `msc_*` wrappers. Upstream describes a web-server connector as a separate project; the examples included here demonstrate library calls. Sources: [Transaction API](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/headers/modsecurity/transaction.h), [C wrappers](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/transaction.cc#L1832-L1904), [upstream explanation of connector separation](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/README.md).

## 8. Distinguish original sources, generated files and submodules

**Parser:** `seclang-parser.yy` and `seclang-scanner.ll` are the relevant language inputs. The generated parser's `.cc`/`.hh` files are also tracked. `src/Makefile.am` explicitly identifies these as the pregenerated parser, and `src/parser/Makefile.am` lists generator inputs and generated files. A grammar change therefore requires deliberate reconciliation of the input and generated result. Sources: [file list](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/Makefile.am#L17-L28), [generator build](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/src/parser/Makefile.am).

Sources: [bootstrap](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/build.sh#L6-L32), [ignore list](https://github.com/owasp-modsecurity/ModSecurity/blob/effb6c0fa031a7bddb3253e0b7ab9ca9a18b5729/.gitignore#L1-L35).

## 9. Reliable orientation for a new task

The following commands are reading aids provided by this documentation. Run them from the repository root; they do not modify source files:

```sh
git status --short
git rev-parse HEAD
git ls-tree --name-only HEAD
rg --files src headers examples test tools build
rg -n 'class Transaction|processRequestBody|msc_process_request_body' headers src
rg -n 'RuleWithOperator::evaluate|RulesSet::evaluate' src
rg -n 'SecRuleEngine|SecRequestBodyAccess' modsecurity.conf-recommended src/parser
```

For tasks involving ignored or hidden files, specify the path explicitly, for example `rg --files .github .oss-scanner`. Assess a change starting with the specific symptom and associated files. This map is a guide; actual code and a traceable test run remain the evidence for behavior and correctness.
